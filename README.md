Комплексный инструмент для **сортировки локальных архивов видео TikTok** и **полной выкачки профилей авторов**.

Проект спроектирован с упором на стабильность в условиях нестабильного интернета, жестких лимитов диска и работы на маломощных устройствах (включая окружения **Android / Termux**): используются атомарная запись файлов, аварийное завершение при нехватке памяти (`Errno 28`), авто-перезапуск веб-драйвера и каскадный обход блокировок.

---

## ⚡ Ключевые возможности

* **Двухэтапная сортировка и синхронизация:**
  1. Скрипт сканирует папку с разрозненными папками видео (вида `7345678901234567890`), восстанавливает авторство по базе данных SQLite (`normal.db` / `storage.db`), через TikWM API или `yt-dlp`, переименовывает файлы в унифицированный формат и раскладывает по папкам `@username`.
  2. Запускает полную синхронизацию профилей каждого обнаруженного автора.
* **Каскадный сбор данных (Dual-Engine Fallback):**
  * Метаданные профиля: Headless Firefox парсит SSR-гидратор (`__UNIVERSAL_DATA_FOR_REHYDRATION__`).
  * Список видео: `yt-dlp` (через `secUid` или ник) $\to$ fallback на `TikWM API`.
  * Скачивание роликов: `yt-dlp` со сжатием $\to$ fallback на прямые потоки без водяных знаков TikWM.
* **Оптимизация под мобильные платформы и Termux:**
  * **Лимит качества (по умолчанию $\le$ 360p):** минимальный расход трафика и диска.
  * **Защита от переполнения хранилища:** перехват ошибки `ENOSPC` (`Errno 28`) с остановкой работы во избежание повреждения архива.
  * **Рециклинг браузера:** автоматический перезапуск Firefox каждые 40 профилей для очистки оперативной памяти.
* **Глубокий архив данных:**
  * Скачивание каруселей фото/слайдшоу (`pic1.jpg`, `pic2.jpg`...).
  * Отдельное сохранение аудиодорожек (`sound.mp3`).
  * Дедупликация аватарок авторов по хэшу SHA-256.
  * Сбор древовидных комментариев и ответов (`comments.jsonl`) вместе с аватарками комментаторов и стикерами/медиа.
  * Скачивание списка лайкнутых видео автора (`likes_YYYY-MM-DD.jsonl`), если они открыты в профиле.
* **Отказоустойчивость:**
  * Запись через `.tmp` и `.part` файлы: битые загрузки не повреждают основной архив.
  * Ведение `synced_authors.txt` для докачки только новых авторов.
  * Изоляция недоступных/удаленных роликов в папку `_unknown_or_deleted` с возможностью повторного прогона (`--retry-unknown`).

## 📂 Структура сохраняемых данных

```text
📁 target_directory/
│
├── 📄 normal.db / storage.db        # Базы данных ссылок (опционально)
├── 📄 synced_authors.txt             # Реестр уже синхронизированных авторов
├── 📁 _unknown_or_deleted/           # Ролики, авторов которых не удалось определить
│
└── 📁 [username]/                    # Каталог автора
    ├── 🖼️ userpic_2026-10-15.jpg      # Аватар профиля (с проверкой SHA-256 дублей)
    ├── 📄 info_2026-10-15.json        # Полный слепок профиля и статы (подписчики, био и т.д.)
    ├── 📄 likes_2026-10-15.jsonl      # Лайкнутые автором видео (если открыты)
    ├── 📄 followers_2026-10-15.jsonl  # Подписчики (если API отдало)
    │
    └── 📁 [video_id]/                # Папка публикации
        ├── 🎬 video.mp4               # Ролик в качестве <= 360p (без ватермарка)
        ├── 🎵 sound.mp3               # Оригинальная аудиодорожка
        ├── 🖼️ pic1.jpg, pic2.jpg      # Изображения (если это фото-пост)
        ├── 📄 video_info.json         # Метаданные (статистика, описание, теги)
        ├── 📄 comments.jsonl          # Дерево комментариев (1 строка = родитель + ответы)
        └── 📁 comment_media/          # Медиа-вложения и аватарки из комментариев
            └── 📁 avatars/
```
🛠 Требования к окружению

1.  Python 3.9+
2.  Системные утилиты:
      - yt-dlp (должен быть доступен глобально через PATH)
      - firefox и geckodriver (для парсинга профилей)

Установка зависимостей Python

pip install requests selenium

📱 Запуск на Android через Termux

Скрипт по умолчанию оптимизирован под системные пути Termux:

pkg update && pkg upgrade
pkg install python ffmpeg x11-repo
pkg install firefox geckodriver
pip install requests selenium yt-dlp

Совет по Cookies: Чтобы снизить риск ограничений со стороны TikTok по сравнению
с гостевым режимом, выгрузите ваши cookie из браузера в формате Netscape
(cookies.txt) и разместите рядом со скриптом (или передавайте в конфигурацию
yt-dlp).

Запуск на ПК (Linux / macOS / Windows):
Если вы запускаете скрипт на обычном компьютере, отредактируйте пути к
бинарникам в начале файла profile_downloader.py:

FF_BIN = "firefox"       # или полный путь к firefox.exe
GECKO = "geckodriver"    # или полный путь к geckodriver.exe

🚀 Использование

Точкой входа является файл main.py.

1. Стандартный запуск (сортировка + полная синхронизация)

Просканирует текущую папку, сопоставит несортированные видео, разложит их по
авторам и выкачает профили:

python main.py

2. Только сортировка без выкачки новых профилей

Привести локальные файлы к нормальному виду, не обращаясь к TikTok за остальными
видео:

python main.py --dir /path/to/archive --skip-sync

3. Выкачка с комментариями и лайками

python main.py --with-comments --likes

4. Работа через Proxy

Поддерживаются SOCKS4, SOCKS5 (рекомендуется протокол socks5h:// для удаленного
DNS-резолва) и HTTP/HTTPS:

python main.py --proxy socks5h://user:password@ip:port

5. Повторная попытка для неопознанных роликов

Если при прошлом запуске часть видео упала в _unknown_or_deleted из-за
тайм-аутов сети или лимитов:

python main.py --retry-unknown

6. Ограничение скачиваемых видео на одного автора

Полезно для ознакомительной выкачки или жесткой экономии диска:

python main.py --max-videos-per-author 20 --delay 3.0

⚙️ Параметры командной строки

| Флаг                      | Описание                                                       | По умолчанию       |
| :------------------------ | :------------------------------------------------------------- | :----------------- |
| `--dir`                   | Рабочая директория с архивами видео                            | Текущая (`.`)      |
| `--proxy`                 | URL прокси-сервера (`socks5h://...`, `http://...`)             | `None`             |
| `--no-comments`           | Не загружать комментарии к публикациям                         | `True` (выключено) |
| `--with-comments`         | Принудительно включить загрузку комментариев                   | `False`            |
| `--likes`                 | Скачивать метаданные избранного (лайков) пользователя          | `False`            |
| `--max-videos-per-author` | Лимит скачиваемых роликов на одного автора                     | Без лимита         |
| `--delay`                 | Задержка между обработкой авторов (в секундах)                 | `2.0`              |
| `--skip-sync`             | Только отсортировать и адаптировать папки, не качать профили   | `False`            |
| `--retry-unknown`         | Повторно попытаться определить ролики из `_unknown_or_deleted` | `False`            |

🛡 Безопасность и обработка сбоев

  - Cloudflare & Rate Limits: Бесплатный шлюз TikWM троттлится с минимальным
    интервалом 1.3 секунды. В случае перегрузки (limit in response)
    автоматически включается экспоненциальный бэкофф.
  - Transient vs Fatal: Скрипт четко отличает временные сетевые сбои
    (TransientError — таймауты сокетов, 429, 502) от реального удаления роликов.
    Папка отправляется в _unknown_or_deleted только при получении
    подтвержденного отказа серверов.
  - Аварийный стоп (No space left): При ловле ошибки ENOSPC выполнение
    немедленно прерывается: недокачанный .part файл удаляется, целостность базы
    метаданных сохраняется.
